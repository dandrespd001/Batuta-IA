# Snapshot contractual K0.11 — evidencia durable

Cada task tiene un identificador único y declara `evidence_mode`.

- `tdd` conserva un comando rojo previo, el verde posterior y una mutación
  dirigida detectada.
- `reconstructed_audit` identifica honestamente trabajo histórico sin rojo
  reproducible; no se presenta como TDD retroactivo.

Cada registro conserva la procedencia en `spec_paths`, pero el hash se calcula
exclusivamente sobre este snapshot inmutable. El fichero vive bajo
`docs/evidence/specs/<sha256>.md`: su nombre, `spec_sha256` y el SHA-256 real de
los bytes deben coincidir.

El validador rechaza campos ausentes, modos desconocidos, rutas duplicadas,
snapshots ausentes o alterados, IDs repetidos, un rojo TDD con salida cero, un
verde fallido y una mutación que no conste como detectada.
